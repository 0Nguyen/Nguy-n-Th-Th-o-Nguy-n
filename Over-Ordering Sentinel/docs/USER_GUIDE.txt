USER GUIDE

DEFAULT LANGUAGE

- The app opens in English by default.
- Vietnamese is still available from the sidebar language selector.

QUICK START

1. Install Python 3.10 or newer.
2. Make sure `python` is available in PATH.
3. Install dependencies with `pip install -r requirements.txt`.
4. Use `START_OFFLINE.bat` for local-only use.
5. Use `START_ONLINE.bat` for local admin control and temporary public sharing.

OFFLINE MODE

- No admin console.
- No public link.
- No cloudflared required.
- Best choice for one-computer review, internal review, or exam use.
- If the offline launcher started the local app itself, closing the browser app window also closes that offline session.

ONLINE MODE

- Opens the local admin console on `http://127.0.0.1:8502`.
- Starts the backend app on `http://127.0.0.1:8501`.
- Can create a temporary Cloudflare share link to the backend app.
- The public user sees the normal app UI only, not the admin page.

CLOUDFLARED

- If `cloudflared.exe` exists in `tools/`, the app uses it.
- If `cloudflared` exists in PATH, the app uses it.
- If neither exists, the app tries to install it automatically with `winget`.
- If `winget` fails, the app downloads the official Windows AMD64 release and stores it at `tools/cloudflared.exe`.

EXCEL WORKFLOW

1. Upload the Excel file.
2. Let the app detect the best data sheet and header row.
3. Review the detected columns.
4. Keep automatic mapping if it looks correct.
5. Fix the mapping manually only if needed.
6. Confirm the mapping to run analysis.
7. Review the report and export the result.

PREPARE THE WORKBOOK

- Try to keep one row per order or service.
- Keep one clear header row when possible.
- Avoid merged cells in the main data region when possible.
- If the workbook contains guide sheets, keep them separate from the main analysis sheet.
- Use consistent insurance-related labels inside the same file when possible.

SMART EXCEL MAPPER

- Detects the data sheet automatically.
- Detects the header row automatically.
- Maps columns automatically.
- Allows manual column correction.
- Normalizes insurance-related values into the app's logic.

MINIMUM COLUMNS

- `DoctorName`
- `PatientName`
- `HasInsurance`
- `CoveredByInsurance`

CORE LOGIC

- `HasInsurance` means whether the patient has insurance.
- `CoveredByInsurance` means whether the specific order is covered by insurance.
- These are different concepts.
- An insured patient can still receive out-of-insurance orders.

READING THE REPORT

- `Overview` and KPI cards describe the size and overall shape of the insured dataset.
- `By doctor` compares doctors inside the same file.
- `By department` compares departments or specialties.
- `Doctor Red Flag Ranking` is a review-priority table, not a verdict.
- `Suspicious High-Cost Procedure` focuses on expensive services or procedures.
- `Required ICD Flags` focuses on diagnosis-context checks.
- `False Red Flag Context` helps remove misleading red flags.
- `Case evidence` shows concrete examples for deeper review.
- `Tool status` explains which tools ran and what limitations they saw.

BUSINESS NOTES

- The app supports professional review, not automatic accusation.
- The report uses review-oriented language such as statistical abnormality and needs review.
